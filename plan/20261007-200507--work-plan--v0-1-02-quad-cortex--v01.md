The user asked to add Quad Cortex support using the official Neural DSP device list and finish previously lacking updates. The planning, simplicity, incremental implementation and test-first skills guide this work. Treat future material changes as new approval boundaries, but carry out ordinary tests and directly related repairs within this scope.

The user-facing objective is to make the existing Quad Cortex choice useful for manual tone setup without weakening the already delivered TMP path. The second objective is to let users obtain a full-song chord chart when guitar isolation is unavailable or unnecessary. Both objectives must preserve honest uncertainty: an audio-derived starting point is not equipment identification, a listed model is not a verified recommendation for every sound, and a chord evidence score is not an accuracy probability.

## Quad Cortex recipe slice

Create a small curated set of clean, edge, crunch and higher-gain guitar starting points using names that resolve to native entries in the inventory. Reuse the existing measured audio feature extraction and ranking concepts where appropriate, but keep QC block construction separate from TMP-specific settings. Prefer a narrow device switch or cohesive module over a broad plugin framework. Preserve the existing result shape where possible so playback and chart features are unaffected.

Respect existing output destinations. An FRFR setup can include amp and cab blocks. A power-amp and real-cab destination must omit simulated cabinets. An amplifier-front setup must not accidentally include an additional amp/cab chain. Preserve transparent warnings about what has been omitted. Use the selected device's identity, firmware and source guide in the GUI, JSON, HTML, saved/reopened results and language switching; do not reconstruct QC results as TMP after a language change.

A hardware control can only be labelled as a real control when an official source establishes it. The model list establishes names and compatibility but not every parameter or knob range. Do not reuse TMP percentages or guess QC defaults. Where exact numerical controls cannot be substantiated, show that device defaults need checking and supply clearly labelled tonal adjustment guidance rather than fictional controls. Numerical suggestions, if added after documentation verification, must be distinguished from measurements and constrained to the documented device range.

Use native devices by default. Plugin-only blocks may appear in the inventory with ownership requirements but are not required for baseline recommendations. Do not contact Neural DSP accounts, read licenses, buy plugins, update physical firmware, send MIDI or write presets to hardware. This release remains an unofficial manual-application aid. Preserve trademark attribution and clarify that neither Neural DSP nor Fender has endorsed it.

Test that every QC recipe block resolves to the intended category and native model, no default recipe uses a plugin or capture accidentally, firmware eligibility is enforced against the declared target, and output routing removes the right blocks. ## Independent song-chord slice

Offer an explicit analysis purpose that distinguishes tone plus chords from chords only. Chords-only must decode the selected original audio, run actual CQT and return a compatible result for the existing chart, editing, playback, JSON reopening, HTML and PDF workflow. It must not run separation, load model weights, rank tone templates, extract guitar tone features, or invent tone metrics. Hide or disable tone-only controls and reports for this mode while keeping source selection, time range, progress and cancellation usable.

Treat chord-only results as a valid outcome, not an error or dummy tone recipe. A file containing piano, bass, voice, drums or a full mix should go through the same full-mixture harmony path. Empty recipe lists and absent tone features must be handled intentionally by the consumer code. On display, make it obvious that tone analysis was not requested. Unsupported modeler choices must not block instrument-independent chord analysis.

Keep minimum and maximum input duration bounds, finite data checks, Unicode filenames and no-overwrite export behavior. Preserve the distinction between absolute original-file seconds and chart-relative seconds. Progress should be monotonic and end at completion only after a result exists; cancellation should report cancellation rather than fabricated results. Check for cancellation around decode and CQT batches and clean temporary audio. Do not make decode cancellation responsiveness claims beyond what is actually tested.

Retain tone-plus-chords as the existing default so users are not silently moved into a different workflow. Do not silently switch failed tone jobs into success with missing tone data. An explicit chord-only path gives the user a reliable alternative without hiding an AI failure. Document that both modes still estimate harmony and do not establish an exact transcription.

## CQT tuning and ambiguity investigation

Preserve true constant-Q analysis and original-mixture channel-magnitude handling. First create controlled detuned chords, noisy and single-note signals, and examples with weak defining tones. Measure whether fixed tuning materially fails compared with a bounded tuning estimate. If the evidence supports an adjustment, estimate tuning from a bounded, representative part of the selected audio rather than retaining an unbounded full-song spectrum. Use safe zero-offset fallback when there is not enough tonal evidence.

Never choose a tuning estimate solely to maximize the number of named chords. Test positive and negative pitch offsets, standard tuning, silence, noise, antiphase stereo and octave spread. Report the applied tuning and fallback status in diagnostics so uncertain behavior is inspectable. Avoid a new heavyweight model or unmeasured whole-engine rewrite. Check the actual installed librosa behavior and primary documentation before relying on tuning units or return semantics.

Investigate low reliable coverage using the existing diagnostic counts, rejected windows and controlled examples. Do not loosen template thresholds merely to hide question marks. Preserve alternatives for identical pitch sets such as C6 and Am7, slash symbols when supported, and explicit unknown spans. Keep chord symbols prominent, evidence and candidates below, and no automatic fingering or stem controls in the chord display.

Run the provided Room 335 sample locally only. Record duration, runtime, counts and coverage without personal paths or audio content. Compare these quantities against the prior baseline, but label them operational metrics, not ground-truth accuracy. Musical correctness requires independent time-aligned annotations; if unavailable, explicitly leave that claim unverified. Do not upload the song or add it to tests, source snapshots or release assets.
