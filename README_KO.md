# ToneMatch TMP 0.0.12

로컬 오디오·영상 또는 권한 있는 Windows PC 재생음을 분석해 Fender Tone Master Pro용 톤 레시피 3개를 추천하는 비공식 Windows 프리뷰입니다. v0.0.12는 오디오 코드 후보를 20종에서 41종으로 확대하고, 음원 없이도 사용할 수 있는 `코드·스케일 사전`을 추가합니다. 12개 근음의 코드 건반도, 12종 스케일·모드, 장음계·자연단음계의 다이어토닉 3화음·7화음을 확인할 수 있습니다. 이론 참고표와 실제 검출 결과는 구분하며 정확한 채보나 물리적 기타 운지를 보증하지 않습니다. 빌드 기준일은 2026-10-02 KST이며 검증 상태는 `QA_REPORT_v0.0.12.json`과 `BUILD_HISTORY.md`를 기준으로 합니다.

추천 카탈로그는 Tone Master Pro 펌웨어 1.8.58과 Model Guide Rev. J의 공개 모델명·컨트롤명을 기준으로 작성했습니다.

> 이 프로그램은 원곡 장비나 Fender DSP를 식별·복제하지 않습니다. `매칭 %`는 정확도 확률이 아니라 측정 특징에 가까운 시작점을 정렬하기 위한 내부 유사도와 분석 신뢰도의 조합입니다.

## v0.0.12 검증 상태

10월 2일 빌드는 자동 테스트 282개(`-W error`), compileall, 소스·EXE의
코드·이론 사전·C++ 자체 진단을 통과했습니다. 10월 3일 최종 EXE의 실제 CPU
모델 전체 곡 제거·취소와 새 압축 해제 무결성·실행 검사를 통과했습니다.
범위는 `QA_REPORT_v0.0.12.json`과 `BUILD_HISTORY.md`를 확인하세요.
이전 릴리스의 통과 기록을 이번 빌드의 결과로 재사용하지 않습니다.

고정 합성 비교(41유형 × 12근음 × 2음색)는 기대한 대표 코드명이
v0.0.11의 480/984개에서 v0.0.12의 984/984개로 늘었으며, 비화음 대조 36개는
두 버전 모두 거부했습니다. 이는 해당 합성 입력만의 검사이지 실제 곡 정확도가 아닙니다.
Room 335도 독립적으로 확인한 시간별 정답 코드가 없으므로 채보 정확도를 산출하지
않습니다. 서명되지 않은 CPU 개발자 프리릴리스이며, 숨긴 창·GUI 없는 진단은
수동 화면·청감·첫 다운로드·네트워크 차단·CUDA·실제 캡처 검증을 대신하지 않습니다.

## 처음 사용하기 전에

- 배포 ZIP은 반드시 별도 폴더에 모두 압축 해제한 뒤 실행하세요. ZIP 내부에서 EXE를 직접 실행하지 마세요.
- `풀믹스/영상 → AI 기타 분리`를 처음 실행할 때 Demucs `htdemucs_6s` 모델 파일을 Hugging Face에서 내려받으므로 인터넷 연결과 여유 저장 공간이 필요합니다.
- `악기 제거`도 같은 모델과 사용자 캐시를 사용합니다. 첫 AI 실행이 어느 기능이든 모델 다운로드가 필요할 수 있습니다.
- 모델은 배포 ZIP에 포함되지 않습니다. 한 번 정상 다운로드되면 같은 Windows 사용자 캐시를 재사용하므로 이후 분석은 보통 오프라인에서도 가능합니다.
- `이미 기타만 있는 파일 → 분리 생략`은 AI 모델을 사용하지 않으므로 첫 모델 다운로드 없이 실행할 수 있습니다.
- `실시간 스펙트럼`은 선택한 원시 입력을 바로 시각화하며 AI 모델을 내려받거나 Demucs를 실행하지 않습니다.
- Reference는 파일 분석 때 만들어집니다. 풀믹스는 분리한 guitar stem, 기타 단독 모드는 디코딩한 소스가 기준입니다. YouTube URL 입력·다운로드는 지원하지 않습니다.
- 포터블 EXE는 호환성을 위해 CPU 런타임을 포함합니다. 자동 모드는 CUDA를 사용할 수 없으면 CPU를 선택하며, 특히 5~20분 곡은 실제 재생 시간보다 오래 걸릴 수 있습니다.
- CUDA는 호환 NVIDIA PC의 소스 개발 환경에 별도로 설치하고 재빌드해야 합니다. 이번 릴리스 PC에는 CUDA GPU가 없어 실제 GPU 추론은 하드웨어 검증하지 못했습니다.

## 로컬 파일 빠른 사용법

1. `ToneMatchTMP-v0.0.12.exe`를 실행합니다. 서명되지 않은 프리뷰라 Windows가 경고하면 배포자가 제공한 SHA-256과 파일 해시를 먼저 비교하세요.
2. 바깥쪽 `톤 분석` 작업 탭에서 입력 방법을 `로컬 오디오/영상 파일`로 선택하고, 직접 보유하거나 분석 권한이 있는 파일을 고릅니다.
3. 시작·끝 시간을 초 단위로 지정합니다.
   - 최소 분석 길이는 3초입니다.
   - 끝 시간을 `0` 또는 빈칸으로 두면 시작 지점부터 파일 끝까지 분석하되 최대 20분에서 멈춥니다.
   - 끝 시간을 입력해도 한 번에 처리하는 최대 구간은 20분입니다.
4. 소스 구성을 고릅니다.
   - 일반 음원·뮤직비디오·밴드 믹스: `풀믹스/영상 → AI 기타 분리 (권장)`
   - 이미 기타만 녹음된 DI·앰프·타브 영상: `이미 기타만 있는 파일 → 분리 생략`
5. 내 기타의 픽업과 Tone Master Pro 출력 연결 방식을 선택합니다. 이 선택에 따라 Amp/Cab 포함 여부와 실제 적용 순서가 달라집니다.
6. `성능 · DSP 진단`에서 연산 장치를 자동, CPU 또는 CUDA로 고릅니다. CUDA를 고를 수 없는 환경에서는 자동을 사용하세요.
7. `톤 분석 시작`을 누릅니다. 전체 단계 진행률과 경과 시간, 모델 다운로드 수신량, 기타 분리 완료 음원 초가 표시됩니다. `분석 취소`는 다운로드 콜백이나 Demucs 내부 블록 경계에서 확인하므로 현재 추론 블록 또는 네트워크 대기가 끝날 때까지 지연될 수 있습니다.
8. 추천 1~3의 블록 순서, 모델, 파라미터와 이유를 비교한 뒤 JSON 또는 HTML 리포트를 저장합니다.
9. Tone Master Pro 본체나 Pro Control에서 값을 수동 입력하고, 원곡과 같은 체감 음량으로 A/B하며 조정합니다.

## 코드·스케일 사전

음원을 넣지 않아도 바깥쪽 세 번째 `코드·스케일 사전` 탭에서 사용할 수 있습니다.

1. 근음을 선택합니다. C부터 B까지 12개 근음을 지원합니다.
2. `코드`, `스케일`, `다이어토닉` 중 분류와 유형을 선택합니다.
3. 코드 기호·구성음·도수와 건반도를 확인합니다. 다이어토닉은 각 도수의 3화음·7화음을 선택해 봅니다.

- 코드: 41종 × 12근음입니다. 메이저·마이너, sus, 디미니시드·어그멘티드뿐 아니라
  6/9, 7·9·11·13, 마이너 메이저 및 변화 도미넌트 코드도 포함합니다.
- 스케일: 메이저/아이오니안, 내추럴 마이너/에올리안, 메이저·마이너 펜타토닉,
  하모닉 마이너, 상행형 멜로딕 마이너, 도리안·프리지안·리디안·믹솔리디안·로크리안,
  6음 마이너 블루스의 12종입니다. 펜타토닉은 코드 유형이 아니라 음계입니다.
- 다이어토닉: 장음계 또는 자연단음계의 음으로 만든 각 도수의 3화음·7화음입니다.
  별도 코드 종류가 아니라 해당 음계 안에서의 화음 관계입니다. 자연단음계 표에
  화성단음계의 장3화음 V 등을 임의로 섞지 않습니다.

C♯ 장음계의 E♯·B♯, E♭ 자연단음계의 C♭처럼 도수에 맞는 음이름을 유지합니다.
같은 건반도 이명동음 이름이 다를 수 있으며, 9·11·13도는 상위 옥타브에 표시합니다.
실제 연주에서는 역위·옥타브·생략음이 달라질 수 있습니다.
사전은 읽기 전용 이론 자료이며 음원의 코드·조성·스케일 자동 검출 결과가 아닙니다.
분석의 미확정 구간을 채우거나 톤 레시피를 바꾸지 않습니다.

## 악기 제거

v0.0.09부터 바깥쪽 작업 탭을 `톤 분석`과 `악기 제거`로 나눕니다.
`악기 제거 / Stem removal` 탭은 Logic Pro의 Stem Splitter와 비슷한
사용 흐름을 지향하는 로컬 보조 도구입니다. Apple Logic Pro와 같은 모델·분리 품질이나
완전한 악기 인식을 구현했다는 뜻은 아닙니다.

1. 로컬 오디오·영상 파일을 고르거나 현재 톤 분석 소스를 가져옵니다.
2. 새 `.wav` 출력 경로와 시작·끝 시각을 지정합니다. 최소 3초이고 한 작업의 최대
   구간은 20분이며 끝 `0`/빈칸은 파일 끝 또는 20분 제한까지를 뜻합니다.
3. 자동/CPU/CUDA 연산을 선택하고 `보컬`, `드럼`, `베이스`, `기타`, `피아노`,
   `Other` 중 제거할 1~5개 파트를 체크합니다. 6개 전부를 제거하는 작업은 허용하지 않습니다.
4. 제거를 시작하면 모델 준비·다운로드와 내부 분리 처리에 따른 진행률 및 경과 시간이
   표시됩니다. 취소는 현재 추론 블록이나 네트워크 대기 때문에 늦게 반영될 수 있습니다.
5. 완료되면 선택하지 않은 stem을 합친 44.1 kHz stereo PCM16 WAV 하나가 생성됩니다.

v0.0.10부터 새 입력을 선택하면 이전 작업 결과·진행률을 지웁니다. 끊어진 심볼릭
링크도 이미 사용 중인 출력 이름으로 취급해 기본 이름을 고르고 실행 전에 차단합니다.
원본은 수정하지 않으며 이미 존재하는 출력 파일도 덮어쓰지 않습니다. 처리 도중
같은 이름의 파일이 생겨도 보호합니다. 남은 stem 합산이 최대 레벨을 넘으면
전체 구간에 같은 감쇠를 적용해 클리핑을 방지합니다. `피아노`는 모델의 피아노 추정
파트이며 모든 건반·신시사이저를 별도 인식하는 것은 아닙니다. 일부는 `Other`에
포함될 수 있습니다. 개별 stem은
디스크에 결과물로 저장하지 않고, 디코딩 파일·중간 mix·부분 출력은 완료·오류·취소 뒤
정리합니다. 음원과 출력은 서버에 업로드하지 않지만 첫 모델 다운로드에는 네트워크가
필요합니다. 분리 결과에는 다른 파트 누출, 빠진 소리, 위상·어택·잔향 변화나 인공음이
생길 수 있으므로 새 WAV를 듣고 확인하고 원본을 보관하세요.

## GUI 없는 실제 모델 진단

개발·오류 재현용으로 `--stem-self-test-source`와 `--stem-self-test-output`을
함께 지정하면 창을 열지 않고 CPU로 기타+피아노 제거를 실행합니다. 완전한 로컬
사용자 모델 캐시만 허용하며 캐시가 없거나 불완전하면 다운로드 없이 실패합니다. 기본 길이 `0`은
전체 음원이되 20분 제한을 따릅니다. 생성하는 진단 WAV는 검사 뒤 삭제하고
`tonematch-stem-self-test/v1` JSON에는 소스·출력 파일명, 소스 해시나 모델
캐시 경로를 넣지 않습니다.

```powershell
& .\ToneMatchTMP-v0.0.12.exe --stem-self-test-source C:\Audio\sample.mp3 --stem-self-test-output .\stem-check-v0.0.12.json
& .\ToneMatchTMP-v0.0.12.exe --stem-self-test-source C:\Audio\sample.mp3 --stem-self-test-output .\stem-cancel-v0.0.12.json --stem-self-test-seconds 31 --stem-self-test-cancel-at 35
```

서로 다른 새 JSON 경로를 사용하세요. 두 번째 예는 31초 구간을 처리하며
보고된 진행률 35%에서 취소를 요청합니다. 현재 추론 블록이나 네트워크 작업 때문에
즉시 끝나지 않을 수 있습니다. 이 검사는 CPU를 많이 사용할 수 있으며 일반
`--self-test-output`이나 실제 화면·청감 검증과 구분합니다.

## PC 재생음 녹음

직접 연주하거나 녹음·분석 권한이 있는 PC 재생음을 Windows WASAPI loopback으로 임시 WAV에 녹음해 분석할 수 있습니다. 일반 로컬 입력 기능이며 사이트 다운로드 제한을 우회하는 대안이 아닙니다.

1. 녹음·분석이 허용되는 소스를 재생 앱에서 준비하고 원하는 지점 직전에 일시 정지합니다.
2. ToneMatch TMP 입력 방법에서 `PC 재생음 또는 오디오 입력 녹음`을 선택합니다.
3. 장치 목록에서 실제 재생에 쓰는 출력의 `PC 재생음`(loopback) 항목을 고릅니다. 기타·마이크를 직접 녹음하려면 `오디오 입력` 항목을 고릅니다.
4. 최대 녹음 시간을 정하고 `재생음 녹음 시작`을 누른 뒤 준비한 소스를 재생합니다.
5. 필요한 구간이 끝나면 `녹음 중지`를 누릅니다. 3초 미만 녹음은 분석할 수 없고, 최대 녹음 시간은 20분입니다.
6. 일반 곡이라면 AI 기타 분리를 선택해 분석합니다.

녹음에는 알림음과 다른 앱 소리도 함께 들어갈 수 있습니다. 알림을 끄고 정확한 출력 장치를 선택하세요. 보호된 재생 경로를 우회하지 않으며, 녹음·분석 권한과 서비스 이용 조건을 지킬 책임은 사용자에게 있습니다.

## 실시간 스펙트럼

`실시간 스펙트럼` 탭은 녹음 목록과 같은 Windows WASAPI 장치를 사용합니다. 기타·마이크·오디오 인터페이스는 `오디오 입력`, PC에서 재생 중인 소리는 해당 출력 장치의 `PC 재생음` loopback을 선택한 뒤 `스펙트럼 시작`을 누르세요. 중지 뒤에도 마지막 측정 화면은 유지됩니다.

현재 구현의 정확한 범위는 다음과 같습니다.

- 44.1 kHz 장치에서 2,048-frame 블록을 받아 초당 약 21.5개 캡처 프레임을 분석합니다.
- Tk UI는 50 ms마다 최신 측정치를 확인해 약 20 Hz로 화면을 갱신합니다. 장치·드라이버 상황에 따라 실제 간격은 달라질 수 있습니다.
- 최신 블록의 입력 파형, 20 Hz~20 kHz 로그 주파수 스펙트럼, RMS/Peak dBFS와 스펙트럼 중심 주파수를 표시합니다.
- 좌우 채널을 먼저 섞어 역상 성분을 지우지 않도록 채널별 FFT 파워를 계산한 뒤 평균합니다. 스펙트럼과 RMS는 최근 4프레임의 선형 파워로 평활화하고 Peak는 그 창의 최댓값을 사용합니다.
- v0.0.09는 포함된 `resources/tonematch_dsp.dll`의 ABI 2 호환성을 확인해 C++ DSP를 우선 사용합니다. DLL이 없거나 호환되지 않으면 NumPy로 폴백하고 실제 백엔드를 표시합니다. 예전 ABI 1 DLL과 혼용하지 말고 새 폴더에 ZIP 전체를 풀어 사용하세요. 일반 EXE 사용자는 컴파일러를 설치할 필요가 없습니다.
- 정렬된 native-endian C-contiguous float32 입력은 Python에서 float64로 올려 복사하지 않고 C++로 전달합니다. float64 입력 경로도 유지하며 다른 배열 배치는 정규화 복사가 필요할 수 있습니다. Python 출력 복사·잠금과 캡처는 남아 있으므로 전체 zero-copy나 하드 실시간 엔진을 뜻하지 않습니다.
- DSP push 처리 시간(ms), 완성 FFT 창 수와 남은 frame을 실시간으로 표시합니다. 엔진의 `input_frames`는 수락한 입력, `completed_windows`는 완성 창, `pending_frames`는 다음 창을 기다리는 입력이며 초기화 때 함께 지워집니다. 처리 시간은 캡처·AI·화면 그리기나 오디오 왕복 지연이 아닙니다.
- C++의 고정 크기 PCM 버퍼는 입력 블록이 FFT 길이보다 짧아도 남은 샘플을 다음 입력과 이어 처리합니다. 완성된 2,048-frame 단위만 표시하며 중지·초기화 때 미완성 부분은 버립니다.
- 작업 스레드와 UI 사이에는 최신 프레임 하나만 보관하는 bounded 큐를 사용하므로, 화면이 잠시 늦어져도 오래된 프레임이나 메모리가 계속 쌓이지 않습니다.
- 장치 충돌을 막기 위해 스펙트럼 모니터링 중에는 녹음·파일 분석·하드웨어 재검사·언어 전환을 함께 실행하지 않습니다.

이 탭은 **선택 장치의 원시 입력을 보는 시각 분석기**입니다. 표시 신호에 Demucs 기타 분리를 적용하지 않고, 톤 특징·템플릿 매칭이나 레시피 추천에도 전달하지 않습니다. C++로 바뀐 부분은 PCM·FFT·평활화 DSP이며 장치 입출력은 여전히 Python/SoundCard의 WASAPI 공유 모드입니다. C++ 장치 콜백, ASIO, WASAPI Exclusive 또는 하드 실시간 처리를 구현한 것은 아닙니다. Python 복사·잠금·캡처 비용이 남으며 전체 곡 Demucs 분석 속도가 빨라졌다고 해석하면 안 됩니다.

## Reference Compare

먼저 로컬 파일이나 녹음 파일을 평소처럼 분석하면, 레시피에 사용한 바로 그 신호에서 Reference 스펙트럼이 생성됩니다. 풀믹스/영상 모드는 Demucs가 분리한 guitar stem, 기타 단독 모드는 디코딩한 소스가 기준입니다. 그 뒤 `레퍼런스 비교`(English: `Reference compare`) 탭에서 오디오 입력 또는 PC 재생음 loopback을 선택하고 `비교 시작`을 누르면 기존 실시간 캡처가 Current가 됩니다.

표와 그래프의 의미는 다음과 같습니다.

- `Low`, `Low Mid`, `Mid`, `Presence`, `Treble`, `Air` 여섯 대역에 `Reference | Current | Δ`를 표시합니다.
- Δ는 `Current−Reference`입니다. 양수면 해당 대역이 현재 입력에서 더 강하고, 음수면 기준에서 더 강합니다.
- 샘플레이트가 다른 두 신호는 공통 주파수 그리드로 보간하며, 전체 에너지를 정규화해 입력 게인보다 톤 형상을 비교합니다.
- 주파수 차이 그래프는 0 dB를 중심으로 같은 방향을 보여줍니다. 나이퀴스트를 넘는 영역과 무음·비유한 값은 안전하게 제한됩니다.
- 새 분석을 완료하면 Reference가 새 결과로 교체됩니다. Reference가 없으면 실시간 입력만으로 비교값을 만들지 않습니다.
- 기준 파일과 같은 음·코드·프레이즈를 연주해야 해석하기 쉽습니다. 연주 음역, 픽업, 분리 잔여음과 녹음 경로도 차이에 영향을 줍니다.
- 기준은 현재 분석 샘플레이트 22.05 kHz에 따라 약 11 kHz까지 비교합니다. 차이 그래프는 ±18 dB 범위로 표시하며 표의 수치는 이 범위로 자르지 않습니다.
- JSON/HTML에는 기준 프로필이 저장됩니다. 실시간 Current와 Δ는 세션 화면에 유지하며 `현재 탭 복사`로 텍스트를 복사할 수 있습니다.
- 입력이 −75 dBFS 이하이면 비교 갱신을 멈추고 마지막 유효 차이를 유지합니다. 아주 약해 측정하기 어려운 주파수 성분에는 공통 계산 하한을 적용합니다.

이 값은 통계적 정확도나 `매칭 %`가 아닙니다. Brightness·Body·Gain·Compression·Ambience 실시간 미터와 Match %, 자동 EQ/TMP 설정 추천·적용, 프리셋 쓰기는 이 버전에 없습니다. 이전 내보내기의 참고 URL 메타데이터는 호환성을 위해 읽을 수 있지만 분석 입력이나 네트워크 다운로드가 아닙니다.

## AI 기타 분리와 DSP 분석

풀믹스/영상 모드의 처리 순서는 다음과 같습니다.

```text
로컬 파일 또는 PC 재생음
  → FFmpeg 44.1 kHz/16-bit PCM 변환
  → Demucs htdemucs_6s, 30초 단위 guitar stem 분리
  → 22.05 kHz 분석 PCM 변환
  → NumPy 네이티브 DSP 특징 + 레벨 정규화 Reference 스펙트럼 추출
  → 코드·보이싱 분석(근거가 약하면 별도 원본 화성 참고)
  → Tone Master Pro 템플릿 매칭
  → 추천 3개와 JSON/HTML 결과
```

선택 구간과 분리된 stem은 임시 작업 영역에서 처리됩니다. 앱은 오디오를 분석 서버에 업로드하지 않지만, 첫 AI 실행의 모델 다운로드에는 네트워크가 사용됩니다.

### 코드·보이싱 결과 읽는 법

시간 연결도 보완했습니다. 한순간의 확장음 후보 때문에 반복되는 화음 후보가
사라지지 않도록, 각 구간에 실제 구성음이 있고 인접 구간에서도 지지되는 후보를
먼저 비교합니다. 없는 음을 만들어 내거나 미확정 구간을 이웃 코드로 채우지는 않습니다.

- v0.0.12는 코드 후보를 20종에서 41종으로 확대했습니다. 7sus2, 11·maj11·m11, 13·maj13·m13, m(maj7)·m(maj9), 6/9·m6/9, 7♭5·7♯5·7♭9·7♯9·7♯11·7♭13, maj7♯5·maj7♯11, add11·m(add11)을 추가했습니다. 유형이 늘어도 해당 음의 근거가 없으면 확장음을 만들어 내지 않습니다.
- C6/Am7처럼 같은 구성음에 여러 이름이 가능한 경우에는 다른 해석을 함께 표시합니다. 검출된 구성음 후보와 코드 템플릿의 구성음을 구분하고, 기타 입력에서 저음이 바뀌면 같은 코드라도 역위 구간을 분리합니다. `근거 점수 n/100`은 정답 확률이 아닙니다.
- 분리 기타 또는 분리를 생략한 입력에서 코드 후보를 찾습니다. 반복되는 음높이 근거를 확인하고 잡음·배음·단음·좌우 역상 때문에 코드가 사라지거나 잘못 생기는 경우를 보완했지만, 완전한 채보 기능은 아닙니다.
- 분리 기타가 매우 약하거나 코드 근거가 부족하면 같은 시작·끝 구간의 원본 믹스를 추가 분석할 수 있습니다. 선택된 결과는 `원본 믹스 화성 참고`로 명확히 표시합니다. 건반·베이스 등도 섞인 화성이지 실제 기타 운지나 역위를 검출한 것이 아닙니다.
- 원본 믹스 참고에서는 기타 줄·프렛 후보, 최저음/역위, 음역·간격 추정을 표시하지 않습니다. 톤 특징·Reference·레시피는 계속 분리된 기타 신호를 사용하며 원본 믹스로 바꾸지 않습니다.
- 시간은 선택한 시작 시각을 더한 원본 파일 기준입니다. 근거가 없는 구간은 `코드 미확정`으로 남기며, 출처·신호 레벨·활성/근거 프레임 진단과 안내를 함께 표시합니다.
- 코드 근거 점수·대안 후보와 검출 구간 비율은 관측 신호의 지지 정도이며 정답률이나 위쪽 톤 매칭 %가 아닙니다. 반주·단음 리프·드럼 위주 구간에서 후보가 없을 수 있으므로 기타 화음이 지속되는 구간을 따로 선택해 비교하세요.

이전 v0.0.11의 역사 기록(현행 검증 아님): 고정 합성 비교(20유형 × 12근음 × 2음색) 480개에서는 기대한 대표 코드명이
기존 v0.0.10의 186개에서 480개로 늘었고, 단음·비화음·잡음 36개는 두 버전 모두
거부했습니다. 이 결과는 해당 합성 입력만의 검사이며 실제 곡 정확도 100%가 아닙니다.
당시 v0.0.11 Room 335 전체 곡 검사에서는 분리 기타가 약해 원본 믹스 참고를 선택했고, 근거가
남은 분석 창은 421개 중 68개(16.15%)였습니다. 이 비율은 정확도가 아니며,
미확정 구간이 많고 독립적인 정답 코드가 없어 실제 곡 채보 품질은 아직 검증하지 못했습니다.

### 작은 화면과 완료 후 상태 표시

창의 초기 크기는 Windows 작업 표시줄을 제외한 작업 영역을 고려합니다. 왼쪽 입력 폼과 하단 분석 상태를 분리하고, 긴 완료·경고 문구는 높이가 제한된 스크롤 영역에서 읽도록 하여 상태 문구가 폼을 아래로 밀어내지 않게 합니다. 결과 제목은 줄바꿈하고 실행 버튼은 별도 행에 배치합니다. 화면 배율·창 크기별 실제 확인 결과는 QA 기록과 구분해 확인하세요.

### 분석 진행률 읽는 법

- 진행 막대와 `전체 단계 xx.x% · 경과 mm:ss`는 개발자 옵션을 켜지 않아도 표시됩니다. 경과 시간은 250 ms UI 타이머로 확인하지만, 진행률을 시간에 맞춰 임의로 늘리지는 않습니다.
- 전체 %는 디코딩·모델 준비·기타 분리·DSP·결과 조립에 배정한 **단계별 진행률**입니다. 남은 실행 시간의 비율이나 ETA가 아니므로 특정 %에서 오래 머무를 수 있습니다.
- 모델 다운로드는 실제 수신량을 MB로 표시하고 전체 파일 크기를 알 때만 해당 파일의 %를 표시합니다. 캐시 사용이나 메모리 로딩은 별도 상태로 표시합니다.
- 기타 분리는 메모리 제한을 위한 30초 외부 조각 안에서도 Demucs 내부 추론 블록이 완료될 때마다 상태를 갱신합니다. `음원 x/y초 처리 완료`는 완료 블록을 기준으로 환산한 오디오 분량이며 경과 시간과 다릅니다.
- CPU 연산 한 번마다 바뀌는 수치는 아니며, PC 성능과 모델·네트워크 상태가 달라 정확한 남은 시간은 표시하지 않습니다. 완료·오류·취소 후에는 마지막 진행률과 경과 시간이 남습니다.

DSP 단계는 포화도, 밝기, 바디, 압축감, 다이내믹, 공간감, 스테레오 폭, 모듈레이션, 딜레이 반복 단서 등을 계산합니다. 출력 연결에 따라 다음처럼 블록을 조정합니다.

- FRFR·헤드폰·USB·PA: `Amp Only`와 별도 `Cabinet`을 포함하고 Cabinet의 로우/하이 컷을 한 번만 적용
- 파워앰프 + 실제 기타 캐비닛: `Amp Only`만 포함하고 Cabinet/IR은 제외하며 기준 Cabinet 정보는 비교 참고값으로 보존
- 기타 앰프 전면 입력: Amp/Cab을 모두 제외하고 이펙트 중심으로 추천

성능 진단은 요청 장치와 실제 선택 장치, CUDA 가용성·빌드, GPU 모델과 총/여유 VRAM, Demucs 전체·조각별 추론 시간, 실시간 배수와 최대 GPU 메모리 사용량을 표시합니다. 실제 분석을 하지 않은 값은 해당 없음으로 남습니다. 연산 선택은 설정에 저장됩니다.

## 첫 AI 모델 다운로드와 캐시

기본 캐시 위치는 다음과 같습니다.

```text
%USERPROFILE%\.cache\huggingface\hub\models--adefossez--HTDemucs-6s
```

`HF_HOME` 환경 변수가 설정돼 있으면 다음 위치를 사용합니다.

```text
%HF_HOME%\hub\models--adefossez--HTDemucs-6s
```

앱은 공식 YAML·safetensors 모델을 캐시에서 먼저 확인하고, 없을 때만 내려받습니다. 공식 경로에서 오류가 나도 알림 없이 예전 모델 다운로드 경로로 바꾸지 않습니다. 캐시를 지우면 다음 AI 분석에서 다시 다운로드합니다. 모델 가중치는 크기와 별도 배포 조건 때문에 포터블 ZIP에 넣지 않습니다.

v0.0.06은 콘솔 없는 EXE에서 출력 스트림이 없어 발생하던 `'NoneType' object has no attribute 'write'` 진행 표시 오류를 방지합니다. 이 오류 자체는 인터넷 미연결을 뜻하지 않습니다. 모델 준비 실패는 서버·네트워크 접근, 캐시 권한·저장 공간, 메모리 부족, 기타 모델·런타임 오류로 나누어 원인과 세부 내용을 표시합니다. 네트워크 오류라면 방화벽·프록시·인증서와 서버 접근을, 캐시 오류라면 저장 공간과 폴더 쓰기 권한을 확인하세요.

## 다른 PC에서 실행하거나 개발을 재개하는 방법

### EXE만 사용할 때

1. 포터블 ZIP 전체를 쓰기 가능한 새 폴더에 압축 해제합니다.
2. SHA-256을 확인하고 `ToneMatchTMP-v0.0.12.exe`를 실행합니다.
3. 새 PC에는 이전 PC의 사용자 캐시가 없으므로 첫 AI 기타 분리 때 모델을 다시 다운로드합니다.
4. 다운로드를 반복하고 싶지 않다면 모델의 배포 조건을 확인한 뒤 이전 PC의 `models--adefossez--HTDemucs-6s` 폴더 전체를 새 PC의 동일한 캐시 경로로 복사하거나, 두 PC에서 같은 구조의 `HF_HOME`을 지정하세요.

### 소스 개발을 이어갈 때

1. 개발 ZIP을 `C:\ToneMatchTMP-dev` 같은 쓰기 가능한 경로에 압축 해제합니다.
2. 압축 안의 `ToneMatchTMP-v0.0.12\source`가 자체 완결된 프로젝트 폴더입니다.
3. 64-bit Python 3.12를 설치하고 패키지 루트에 `.venv`를 새로 만듭니다. 기존 PC의 가상환경은 절대 경로와 네이티브 패키지를 포함하므로 복사해 재사용하지 마세요.
4. `source\requirements.txt`로 의존성을 설치합니다. ZIP의 네이티브 DLL로 소스 실행이 가능하며, C++ 수정·재빌드에는 아래 고정 버전 컴파일러가 필요합니다. 테스트에서 C++ 검증이 실제 실행됐는지도 확인하세요.
5. `DEVELOPER_HANDOFF_KO_EN.md`와 `BUILD_HISTORY.md`를 먼저 읽은 뒤 작업을 이어갑니다.

```powershell
Set-Location C:\ToneMatchTMP-dev\ToneMatchTMP-v0.0.12
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install --upgrade pip
& .\.venv\Scripts\python.exe -m pip install -r .\source\requirements.txt

Set-Location .\source
& ..\.venv\Scripts\python.exe -m unittest discover -s tests -v
& ..\.venv\Scripts\python.exe app.py
```

CUDA 지원 NVIDIA PC에서 소스 빌드를 가속하려면 위 기본 환경과 테스트를 먼저 확인한 뒤 `source`에서 다음을 실행합니다.

```powershell
.\enable_cuda.ps1
& ..\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\build.ps1
```

`enable_cuda.ps1`은 `requirements-cuda126.txt`에 고정된 PyTorch CUDA 런타임을 설치합니다. NVIDIA 드라이버·GPU·PyTorch CUDA 빌드가 모두 호환되어야 하며, 설치만으로 모든 PC에서 CUDA가 보장되지는 않습니다. 가상환경을 다른 PC로 복사하지 말고 PC마다 다시 만드세요.

공개 소스는 `git clone https://github.com/JH-Prime/ToneMatchTMP.git`으로 받을 수도 있습니다. Git 저장소는 용량이 큰 `resources\ffmpeg.exe`를 제외하므로, 소스 실행·빌드 전 포터블 ZIP의 `source\resources\ffmpeg.exe`를 같은 위치에 복사하세요. `build.ps1`은 프로젝트의 형제 폴더에 있는 `..\.venv`를 사용합니다. 자세한 인수인계·빌드·검증 절차는 `DEVELOPER_HANDOFF_KO_EN.md`를 참고하세요. Codex나 다른 개발 도구에서 재개할 때는 `source` 또는 Git clone 폴더를 작업 폴더로 열고 두 인수인계 문서를 먼저 읽도록 지시하세요. 대화 기록이나 이전 PC의 임시 파일은 ZIP에 자동 포함되지 않습니다.

#### C++ 엔진을 수정·빌드할 때

[공식 Zig 0.15.2 Windows x64 ZIP](https://ziglang.org/download/0.15.2/zig-x86_64-windows-0.15.2.zip)의 SHA-256이 `3a0ed1e8799a2f8ce2a6e6290a9ff22e6906f8227865911fb7ddedc3cc14cb0c`인지 확인하고 프로젝트 바깥에 압축 해제합니다. 컴파일러는 배포 ZIP에 넣지 않으며 일반 EXE 실행에는 필요하지 않습니다.

```powershell
& ..\.venv\Scripts\python.exe tools\build_native.py --zig C:\Tools\zig-0.15.2\zig.exe
& ..\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\build.ps1 -ZigPath C:\Tools\zig-0.15.2\zig.exe
```

또는 `TONEMATCH_ZIG` 환경 변수로 `zig.exe` 경로를 지정합니다. Git에는 `native\tonematch_dsp.cpp`·헤더, `native_dsp.py`, 테스트와 빌드 스크립트를 추적하고 생성된 DLL은 제외합니다. 포터블 개발 ZIP에는 이 소스와 DLL을 함께 포함합니다. DLL 누락으로 NumPy에 폴백한 테스트를 C++ 릴리스 검증으로 기록하지 마세요.

## 중요한 한계

- Demucs 6-stem의 guitar 출력은 실험적인 추정입니다. 키보드·보컬·심벌이 남거나 기타가 일부 사라지고, 위상감·어택·잔향에 인공음이 생길 수 있습니다.
- AI가 분리한 stem이 톤 특징을 계산할 수 없을 정도의 무음이면 분석을 중단합니다. 신호가 남아 있지만 매우 약하면 경고와 코드 전용 원본 화성 참고를 제공할 수 있으며, 그 경우도 톤 추천을 정확한 기타 분석으로 간주하면 안 됩니다. 실제 기타가 잘 들리는 구간을 선택하세요.
- 긴 곡의 외부 처리는 30초 단위지만 CPU/GPU 추론 시간은 PC 성능, CUDA 호환성과 VRAM에 크게 좌우됩니다.
- PC 재생음 녹음 품질은 Windows 출력 장치, 드라이버, 시스템 음량과 다른 앱 소리에 영향을 받습니다.
- 코드·보이싱 분석은 NumPy 스펙트럼의 피치 클래스 단서를 이용하는 추정 기능입니다. 복잡한 왜곡, 드롭 튜닝, 카포, 벤딩, 베이스·건반 누출에서는 코드명·최저음·음역이 틀릴 수 있으며 악보 채보 결과로 간주하면 안 됩니다.
- 취소되거나 중단된 AI 분석을 중간 조각부터 재개하는 체크포인트는 없습니다. 완전히 내려받은 모델 캐시만 재사용되며 분석은 처음부터 다시 실행합니다.
- 악기 제거는 선택한 stem을 정확히 지우는 편집기가 아니라 AI 추정 stem에서 나머지를 재합성하는 기능입니다. 개별 stem 내보내기, 작업 체크포인트, 원본/기존 파일 덮어쓰기와 Logic Pro 동등 품질을 제공하지 않습니다.
- 추천값은 완성 프리셋이 아니라 시작점입니다. Gain → Cab/Mic → EQ → Delay/Reverb 순으로 조정하세요.
- Reference Compare는 레벨 정규화된 주파수 차이이며 통계적 정확도·매칭 확률이나 완성된 실시간 톤 매칭이 아닙니다. Brightness·Body·Gain·Compression·Ambience·Match % 미터와 자동 EQ/TMP 추천은 후속 범위입니다.
- v0.0.08에서 분리한 C++ 실시간 PCM 누적·FFT·평활화 엔진을 v0.0.09에서 float32 입력·진단으로 보완합니다. 장치 입출력·UI·AI·오프라인 분석·Reference 비교 계산은 Python 기반이며 ASIO·독점 모드·하드 실시간·자동 기기 쓰기는 포함하지 않습니다. NumPy도 이미 네이티브 FFT를 사용하므로 성능 차이는 각 버전 QA의 실제 측정 범위로만 해석하세요.
- Tone Master Pro/Pro Control은 임의 블록과 모든 값을 쓰는 공개 API를 제공하지 않습니다. 기기 연결, 프리셋 자동 생성·전송, 노브 자동 조작을 하지 않습니다.
- JSON은 분석 데이터이며 Tone Master Pro가 가져오는 `.preset` 파일이 아닙니다.
- Tone Master Pro 외 장치 프로필은 현재 선택 자리만 있으며 분석은 지원하지 않습니다.

공유 권한이 있는 다음 자료가 있으면 모델·컨트롤 범위와 특징→설정값 보정을 개선할 수 있습니다.

- 펌웨어 1.8.58에서 Pro Control로 내보낸 빈 프리셋과 단일 블록 프리셋
- Gain 또는 Cabinet 마이크 위치 하나만 다르게 저장한 프리셋 쌍
- 같은 연주의 드라이 DI와 해당 프리셋 처리 후 WAV
- 기타 종류·픽업·출력 방식·펌웨어가 기록된 비교 샘플

비공개 `.preset` 형식은 구조와 체크섬을 확인하기 전 임의로 생성하지 않습니다. 상용 프리셋이나 타인 저작물은 허가 없이 제공하지 말고, 공유 전 개인정보를 지우고 원본을 백업하세요.
